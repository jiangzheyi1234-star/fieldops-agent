# 部署与交付操作手册

## 本地部署

按 README 创建 Python 虚拟环境、安装锁定依赖并构建前端。生产构建由 FastAPI 同域提供，默认绑定 `127.0.0.1:8765`。状态保存在 `data/fieldops.db`；该目录不提交到 Git。`/api/meta` 用于检查版本和模型是否配置，`/docs` 可查看 API。

## 容器部署

```bash
docker build -t fieldops-agent:local .
docker run --rm -p 127.0.0.1:8765:8765 -v fieldops-data:/app/data fieldops-agent:local
python scripts/smoke.py --base-url http://127.0.0.1:8765
```

容器采用 Node 构建前端，Python 运行后端，以非 root 用户启动，并提供 HTTP 健康检查。健康检查只用于判断进程可用；交付验收仍需走业务流程。默认不向外部网络暴露端口。真实多用户部署需要另行增加身份认证、权限管理、备份、TLS 与组织审批。

## 交付流程

1. 新建工单，选定合成故障场景。记录客户现象和交付约定。
2. 运行诊断。核对 E01 的配置差异、E02 的业务探测和对应 runbook。
3. 审查变更字段和值。审批绑定当前方案哈希与配置版本；方案变动或重复执行会被拒绝。
4. 执行配置更新。系统在新数据库和新服务沙箱中独立重放配置，检查两类问题、引用、隔离与约定。
5. 导出 ZIP。`manifest.json` 记录各文件的 SHA-256；`events.json` 记录审批、变更和验证事件及前序哈希。
6. 七项全部通过才可确认业务验收。上游维护应升级处理，内容漂移应人工复核。

## 故障和恢复

| 现象 | 检查 | 处理 |
| --- | --- | --- |
| 模型模式不可用 | `/api/meta`；服务器环境的三个 `FIELDOPS_MODEL_*` 变量 | 配置支持原生工具调用的提供方；使用离线模式验证工程流程 |
| 诊断失败 | 工单状态 `diagnosis_failed`，模型响应格式和工具参数 | 不会修改配置；修正提供方设置后新建案例重试 |
| 执行返回 409 | 工单状态、方案哈希、配置版本 | 获取当前工单；只审批当前方案，避免重复执行 |
| 进程重启 | 保留 `data/fieldops.db` 或容器卷 | 工单和待审批状态可恢复；正在诊断/执行时的崩溃不自动续跑 |
| 健康检查成功但业务失败 | 独立验收检查和 E02 | 使用业务结果核验，不把 200 当成交付成功 |

## 客户演示与验收口径

客户只需要关注：发生了什么、有哪些证据、准备修改什么、修改后业务是否恢复、如何复核。界面的公开演示为真实记录回放，完整后端执行在本地进行。演示数据不代表真实客户成果；没有模型密钥时不得展示“真实大模型准确率”。

## 测试报告组成

`evaluation/results/report.md` 给出总体结果，`summary.json` 记录语料哈希和方法统计，`trials.jsonl` 保存每个案例的检查、工具调用、审批与事件。语料修改必须更新版本和基线预期，不能只选择成功案例重跑并覆盖失败。
