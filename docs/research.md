## 为什么选这个业务

目标岗位要求驻场开发、模型平台二次开发、系统联调、故障处理、测试和验收材料。选择企业知识助手交付链路，可以在一个可运行案例中展示这些动作：网关接入 → 索引约定 → 导入任务 → 租户访问 → 业务验收 → 材料交付。该判断是基于岗位截图与上述资料的工程选择，不是论文对求职效果的结论。

主展示案例同时注入四处配置漂移。首个 HTTP 404 会遮蔽后面的维度和导入错误，所以系统还需要读取配置并对照客户约定。单次错误匹配只修复第一处，完整流程在批准后一次更新四项，再通过业务重放证明结果。

## 如何突出可验证的优势

1. **可运行**：在本地 HTTP 服务中故障会改变实际响应，界面与报告读取真实 API 结果。
2. **可解释**：每项变更有配置证据、探测证据和检索到的手册来源；模型编造 ID 或越界值会被程序拒绝。
3. **可验收**：进程存活、业务回答、正确引用和租户隔离分别核验。故障升级和人工复核不计作业务恢复。
4. **可复测**：固定案例语料哈希，公开每例检查、最终配置哈希和轨迹；使用相同语料比较基线和门禁消融。
5. **可交付**：生成配置、证据、检查报告、客户操作说明和哈希清单，不只有聊天记录。

## 当前证据的局限

54/54 仅表示支持的合成配置故障在测试参数上都恢复。其余 12 例保持失败，说明结果门禁有效，但不能证明对真实生产系统的根因诊断能力。离线模式依据可检查的交付约定生成确定性方案，可选 LLM 接口虽然可运行，尚未使用真实模型进行质量测评。下一轮能力评测应引入不在手册内的故障、无完整约定的客户现场、真实检索服务和多模型重复试验。
