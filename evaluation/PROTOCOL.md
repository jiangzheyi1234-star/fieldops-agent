# 合成故障回归评估协议

## 数据和分割

`cases.json` 是固定的 96 个原创建案例：12 个场景，每个 8 个参数种子。101/102 为开发集，共 24 例；201—206 为测试集，共 72 例。测试场景包括 8 类单项配置故障、4 项同时漂移的复合故障、上游维护、回答内容漂移和健康对照。

变体改变客户 ID、索引版本、向量维度、上游耗时和错误超时预算。它们属于**已知模板的新参数回归**，不是未见故障类型的盲测。语料、生成器和测试集公开；无法声称无训练污染或生产泛化。

诊断器收到客户工单、配置/交付约定和工具结果；不会收到案例名称、种子、评估预期状态或注入器内部设置。工具探测可观测实际业务响应。交付约定提供允许配置，这是刻意定义的受限运维任务。

## 验收与指标

验收器独立创建新 SQLite 数据库和新的服务应用，用最终配置与固定客户数据发起 HTTP 请求。七项检查全部通过，才记为 resolved。它不会读取方案总结判断成功，也不要求动作与参考顺序一致。

- **业务成功率**：resolved / 72，包含健康对照。上游维护和内容漂移即使正确升级/复核仍为失败。
- **可修复故障恢复**：resolved / 54，只包含已支持的单项和复合配置故障。
- **误报完成**：诊断流程声明 `verified`，但独立验收失败的数量。
- **流程正确**：健康/可修复案例 verified，上游维护 escalated，内容漂移 needs_review，且完成声明与独立结果一致。
- 工具调用数量来自证据记录。耗时来自本机计时，只供复现参考，不比较云端模型延迟。

## 比较方法

| 方法 | 行为 |
| --- | --- |
| no_op | 保留原配置，用进程健康声明完成；检验空操作能否蒙混过关 |
| one_shot | 同样读取配置并进行业务探测，只按首个显式错误检索手册并修复一项，保留独立验收 |
| without_replay | 与完整确定性修复器相同的方案、证据、审批和受限更新；移除独立结果作为完成门禁，改用 liveness 声明完成 |
| fieldops | 全量对照配置约定，逐项检索手册，批准后更新，在新实例中按全部业务结果决定完成状态 |

无门禁方法在无变更的诊断分支仍可能收集独立检查，但不使用它限制完成声明。该消融隔离的是**完成决策门禁**；不能用其本机耗时来宣称省去了所有验证开销。所有方法最终都由同一个独立验收器评分。

## 复现和回归门禁

```bash
python -m evaluation.run --split test
python -m evaluation.check
```

第二条命令核对固定语料哈希、案例数量、逐例检查的统计一致性和基线预期。它是当前版本的回归门禁，不是隐藏测试或防作弊认证。原始轨迹包含时间戳和随机工单 ID；比较结果时应按 case_id / method / 检查名称对齐，不比较字节相同。

## 模型测评

当前公布的结果完全来自离线模式。`llm_run.py` 仅在用户明确运行且配置提供方后发起真实模型调用；按相同程序化终态评分并单独存储成绩，默认不进入 CI。适配器单元测试使用模拟提供方，不计入真实模型测评。真正比较模型时还应固定模型版本、提示词、工具预算、费用记录，并每例重复多次。
